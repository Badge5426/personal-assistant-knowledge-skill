# Space-first 测试报告

## Native RC2 已审发布：未知作者资料冲突修正

Native RC2 已通过本轮独立源码复审，unknown 作者冲突 P2 已关闭。基线是已发布 Space RC2.1；本轮结论来自新增适配及修复的独立审核，旧 PASS 不替代新审核。新增 native_history.py 是无网络的回执规范化工具，Agent 仍调用普通桌面 Work 现成的 list_threads/read_thread/list_archived_threads；无新连接器、权限、后台任务或 app-server 启动。

Python 3.9 与 3.11 的 RC2 验证见私人核验回执，离线总数 123（原 74 + native 31 + 三来源 17 + memory/materials 覆盖 1）。新 tests/fixtures/native-history.json 完全虚构成人项目，沿用实际 native 返回结构；覆盖真实 host 分流、用户/助手区分、跨页去重、空末页、错/环形游标、摘要、截断、未知、消息 ID 冲突、记录日不当确认日、旧新纠错证据保留及重复输出不覆盖。测试不连接真实账户或 Space。

mixed-sources.json 为完全匿名三来源语义标注夹具，不是自动自然语言抽取或真实账户三来源导入。历史、衍生 memory、已有资料同一事实合并一个值并保留三种出处，不按数量增加独立证据；较新直接用户明确纠正替代较早对应说法，旧证据保留。较晚/未知的矛盾资料保持冲突，memory 不可声明直接证据或纠正，助手建议不成为用户目标。已知字段不进入补问清单；只留下缺项/冲突。

RC2 本地安装与已有官方系统安装器的离线夹具路径均核对 27 个文件，拒绝覆盖；发布后的远端固定 commit 干净安装证据以 README 安装 pin 和发布回执为准。工程环境的官方 quick_validate 因缺 PyYAML 未运行成功，未安装依赖；本包 scalar frontmatter、引用、语法、JSON 及常见私密标识检查通过。独立审查环境用已有 PyYAML 6.0.3 对未改动的 SKILL frontmatter 和 agents YAML 实际 safe_load 并核对字段类型通过；这不是官方 quick_validate 通过。

RC1 独立审查发现：已有用户证据时，较晚/日期未知且作者未知的矛盾保存资料被忽略，误报 known。RC2 仅修正该 P2：未知作者资料不获得用户事实权威，但阻止未经日期核实的对应旧值被明确纠正标记替代；较晚/同日/日期未知的矛盾值保留 conflict 并进入补问。确知较早资料保留证据，不凭空覆盖较新用户事实；对应较早值仍允许明确用户纠正。新增 7 项回归；修正前 17 项三来源测试出现 5 次断言失败（含参数子例），修正后随全套 123 项核验通过。冻结 RC1 保留，本次 RC2 独立复审 PASS 已关闭该 P2。

本轮真实只读能力核查：普通桌面 Work 的 list_threads 返回有界近期列表，当前 limit 最大 50 且无分页；对一条明确获准的非敏感本机项目线程，read_thread 返回用户原话、助手正文和 turn/item ID，4 页、22 turn、25 用户消息、100 助手正文按真实游标读到末页；不证明附件、压缩前历史或全账户全集。已有获准 memory 定向检索成功，仅作摘要线索。个人上下文检索明确“此会话不可用”，未提供授权动作。原“read_thread 常为摘要”不能作为固定分类，现按返回结构和截断/游标判断。

真实来源另做私人事实草稿和去重/纠错检查；不公开线程正文、ID、日期、项目名称或本机路径，不写 Space、不覆盖当前项目状态。RC2 的实际安装、归一化和只读提炼回执均与匿名结构测试分开交独立审稿；真实历史→当前私人 Space 写入、全账户枚举、客户端自动发现和独立新模型仍未验收。

此前“工程只读选定的虚构源”是下列基线建库测试的范围说明，移至此测试报告；不是生产 Skill 的只读夹具限制。生产流程允许整理已授权真实资料，先填已有已知项，再问缺项。

## RC2 独立审计修复

P2-1：full+非空 next_cursor 在任何状态变更前拒绝；回归同时验证拒绝且不变、partial+cursor 保留继续位置、full+null 可接受。旧账本遇该非法组合在 summary 保守计 partial。

## RC2.1 同范围读回失效修复

一个受影响角色先通过读回，后续读回失败时，撤销该角色在 change_set 中的验证并恢复 pending；记录修订以便保存失效状态。新增顺序回归：goals 成功 → goals 失败 → projects 成功仍 pending；重验 goals 后才 verified，已整体 verified 后再失败也回到 pending。覆盖旧值、缺内容、错误 Page、部分读回和缺写权限。冻结 RC2 保留。此修复后已在正常 Work 中显式读取安装 RC2.1 验证空白首次建库、增量维护、受控续跑与重复阶段；没有重跑被拒 CLI，自动发现仍未验收。
