已在具备 Space 工具的正常 Work 任务中，通过显式读取已安装 SKILL.md，使用 3 个完整匿名来源验证空白建库、资料整理、逐页读回、增量维护、受控续跑和重复调用不新增页面。安装本身不运行建库或增加权限。客户端自动发现、独立新模型、UI 渲染，以及真实账户历史发现到逐会话整理完整流程尚未验收；三个匿名来源不代表全部聊天。

Python 3.9.6 与 3.11.17：74 项 unittest 通过。原 46 项本地档案/纠错/安装测试保留；28 项 Space 私人账本不变量，包括目录/父页、重复防护、根/部分页恢复、未知响应、同名不认领、读回失败、缺权限、隐私缺失、摘要不冒充完整、来源去重/覆盖、手改/版本、部分操作与 unknown 优先。模拟回执是 mock，不是连接态证明。

`python3 scripts/check_package.py` 检查文件、链接、语法和常见私人标识；不是完整隐私审计或一般 YAML 验证器。公共源码另做逐文件范围审核，不含真实档案、Page/Library ID、凭据、本机路径或原始日志。

本包 installer 实际复制 25 个 Skill 文件到全新项目的 .agents/skills；实际可恢复卸载、重装和逐字节安装清单核对。安装不运行建库，不更改配置、权限或下载依赖。系统 installer 的远端安装须使用 README 中实际验证后的完整代码 commit，核对 25 个文件字节与测试结果；本地回执不代替远端证据。

## 显式加载已安装 Skill：空白首次建库

在具备 Space 工具的正常 Work 任务中，先核对安装的 25 个文件与冻结 RC2.1 一致，再显式读取项目内 .agents/skills/maintain-personal-context/SKILL.md 及首次建库、历史覆盖、维护、保存恢复规则，完整读取安装夹具 A/B/补充三个匿名来源。之后才从不存在的新映射执行首次建库。不是旧工程编排根页的追认，也没有使用失败的独立执行器占位。

- 指定名称查重按真实游标到结束，包含空页；无匹配后先持久化 pending，再执行一次 create_space，立即保存实际 Space/root 回执。
- 七类、工作台、稳定档案、日志、精选长期结论及覆盖记录共 13 页。每次子页创建前保存 pending，返回后保存真实 ID，逐页完整读回 parent、Space、正文、标记及可写性。
- 13 页的实际分享回执均有 owner、直接分享空、继承覆盖完整且空、无后续游标；不更改分享。该证明仅针对已映射的 13 页，不当作全账户页面枚举。
- 整理自述事实、助手建议和第三方评价；纠错 8→3→4 年保留旧证据及替代链，当前仅最新明确纠错。成果事件日与历史保存确认未知；当前保存授权与记录日期分开。未来目标是计划，临时焦虑只进日志，未经确认不生成长期人格结论。
- 工作台保存最多三项必要补充问题及对应保存位置，不替虚构人物回答。
- 全部受影响页独立读回后完成。重复阶段重新读取安装规则与同一夹具，13 页 ID/hash/正文相同，新增 Space、页面、页面编辑均为 0，来源仍为 3。
- 新旧测试 ID 集合不相交，旧映射逐字节不变；用户真实知识库未修改。实际请求、回执、完整读回、私有证明和状态顺序保留在公开包外供独立复核。

## 早期工程直接编排及故障验证

更早的工程 Agent 工具编排另行记录：根页创建早于新版 SKILL 正文，故不作为上述已安装 Skill 空白首次验收的依据。其实际故障与恢复范围如下：

- create_space 一次；返回真实 Space/root 映射。
- 根 + 七类 + 工作台 + 四个分层子页，共 13 页；逐页独立 read_page，正文、实际 parent、Space、can_write 和私有分享证据通过。
- 全部页面分享检查返回 owner、shares=[]、inherited_access.complete=true、sources=[]、无分页遗漏；没有修改分享。
- 根建成后的受控暂停、部分分类后受控暂停：持久化映射，之后重载状态续建。这是 checkpoint 中断，不声称服务崩溃。
- 第二次调用只读原映射 13 页：13 个唯一 Page ID，正文块逐项相同，零 create/页面 write，人工备注模拟 N-3 保留。
- 虚构补充在原页增量保存：目标优先排版、助手先给三项选项、技能纠错 8→3→4 年；旧证据/日期保留，开始日期未知，助手建议/第三方评价与事实分开，临时焦虑只在日志。
- 实际 edit_page 混合 literal patch：第一项保存，第二项 stale hash 拒绝；读回核验成功项和 N-3，没有回放成功项。
- 模拟创建丢响应：真实对象已建，账本故意置 unknown，重复创建被阻止。真实 list_pages 缺 partial_results，因此不宣称唯一；用保留的原始创建回执核对后恢复。没有模拟成真实服务故障，也没有证明丢失原始回执时能自动恢复。
- 缺工具、读拒绝、写失败、读回失败与分享未知通过离线 fault fixtures 验证，未改变真实账户权限来制造故障。

未验证 UI 渲染。已保存正文与权限验证不证明浏览器布局。上述显式加载与早期编排均不冒充独立新模型从客户端自动发现到完整账户整理的流程。

## RC2 独立审计修复

P2-1：full+非空 next_cursor 在任何状态变更前拒绝；回归同时验证拒绝且不变、partial+cursor 保留继续位置、full+null 可接受。旧账本遇该非法组合在 summary 保守计 partial。

P2-2：补充后列出主条目和受影响投影，读回全部一致才完成；消息日期不自动成为保存确认日期。虚构 B2 成果的事件日/历史保存确认改为未知，本次保存确认取明确 2026-10-10 建库授权。现有项目页引用 F05 主目标“优先排版”，相关结果页分别标日期及来源，无新增页。RC1 冻结证据保留，RC2 修复事件另给审稿。

## RC2.1 同范围读回失效修复

一个受影响角色先通过读回，后续读回失败时，撤销该角色在 change_set 中的验证并恢复 pending；记录修订以便保存失效状态。新增顺序回归：goals 成功 → goals 失败 → projects 成功仍 pending；重验 goals 后才 verified，已整体 verified 后再失败也回到 pending。覆盖旧值、缺内容、错误 Page、部分读回和缺写权限。冻结 RC2 保留。此修复后已在正常 Work 中显式读取安装 RC2.1 验证空白首次建库、增量维护、受控续跑与重复阶段；没有重跑被拒 CLI，自动发现仍未验收。
